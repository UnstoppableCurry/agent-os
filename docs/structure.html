仓库结构

下列树按撰写本站时仓库中存在的路径整理。CLAUDE.md 第三节的树（含 router.rs、agent/、query.rs、loader.rs）已过时。

顶层目录

路径 README 说明 当前可见内容
backend/ Rust 后端（Axum + Tokio） src/{api,bot,engine,memory,sensor,skill,types,main}.rs；健康接口写版本 0.1.0
app/ SwiftUI 主 App（iOS + macOS） Swift 源码、SPM 清单、XcodeGen project.yml、Xcode 工程
lifekit/ LifeKit Swift Package（SDK） Models / Transport / EventBuffer / Privacy，以及单元测试
memory/ 记忆文件系统 stream、crystal、mirror 模板、sensors YAML、bedrock 文稿
skills/ Skills 扩展库 一份 README，以及 git-workflow/SKILL.md
Makefile 构建与测试入口 backend / lifekit 目标；无 app 目标
docs/ （本站新增） 仅静态概览，由 Actions 发布，不包含记忆原文

backend 模块

  • bot/：管理器、supervisor、会话存储、事件缓冲、空闲回收（默认 30 分钟任务）。
  • engine/：进程句柄与三个 CLI 适配器。
  • memory/：流与晶体文件存储。
  • api/：health、bots、events、memory、ws 的处理函数（路由集中在 main.rs）。
  • sensor/mod.rs 与 skill/mod.rs：注释写明「future expansion」，视为桩。

平台声明（只引用清单）

  • app/Package.swift：platforms: iOS 17, macOS 14；产品是名为 AgentOS 的 library，并排除 @main 的 AgentOSApp.swift。
  • app/project.yml：应用目标 platform: macOS，部署目标 macOS 14.0，包名 com.unstoppablecurry.AgentOS，营销版本 0.1.0。未见 iOS 应用 target。
  • 源码里有 #if os(iOS) 分支（例如创建表单导航栏、设置页键盘类型）。
  • lifekit/Package.swift：同样声明 iOS 17 与 macOS 14。

因此：清单表达了编译目标意图；README 的「iOS + macOS」与 Xcode 工程「仅 macOS 应用」并存。本站不把它写成已在两套系统上验证发布。

memory 与 skills

晶体目录里有 identity、people、goals、projects、state、patterns、body、wealth、insights、skills、time 等 Markdown 文件名。镜像有 weekly / monthly 模板。传感器目录有 health、calendar、contacts、finance、screen、git 的 YAML 配置草稿。

这些是仓库内的设计/数据文件，不等于对应采集器已接通。本站不转载其中的个人身份内容。

skills/README.md 规定每个 Skill 一个目录加 SKILL.md，并列出内置 git-workflow（always 加载）。后端 skill 模块尚未加载这些文件。

环境变量（文档 vs 代码）

变量 CLAUDE.md 源码使用
AGENT_OS_PORT 默认 3000 未读取；端口写死 3000
AGENT_OS_DB_PATH SQLite 路径 未见对应依赖或读取
AGENT_OS_MEMORY_DIR 默认 ./memory 有读取；缺省路径与文档不同
AGENT_OS_DATA_DIR 未列 Bot 与会话数据目录
ANTHROPIC_API_KEY 列出 后端 crate 未出现该键名
AGENT_OS_LOG_LEVEL 默认 info 使用 tracing 的 RUST_LOG 风格过滤器，未见此键
CLAUDE_PATH / KIMI_PATH / CODEX_PATH 未列 适配器用来定位 CLI
