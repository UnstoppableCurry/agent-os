架构（以源码为准）

CLAUDE.md 仍描述 router.rs、agent/、query.rs 等路径。当前后端是 api / bot / engine / memory / sensor / skill。下表与框图只反映能打开的文件。

分层（README + 源码）

app/ SwiftUI：机器人列表、聊天、设置
lifekit/ 事件缓冲、HTTP 上报、WebSocket 监听
backend/ Axum：Bot 管理、SSE、事件摄入、晶体读取
memory/ 流 JSONL、晶体 Markdown、镜像模板、根基文稿
engine 适配器 拉起本地 claude / kimi / codex 进程

这是目录关系示意，不是运行时截图，也不是性能或可用性证明。

后端实际注册的路由

摘自 backend/src/main.rs。设计文档里的 /api/bots、/api/memory/query、/api/skills、/ws 没有按原文出现。

当前 Axum 路由
方法 路径 源码行为（简述）
GET /health 返回 status/ok、service/agent-os、version/0.1.0
GET / POST /v1/bots 列出或创建 Bot
GET / DELETE /v1/bots/{id} 查询或删除 Bot
POST /v1/bots/{id}/messages 发消息，以 SSE 推送引擎事件
GET /v1/bots/{id}/ws 该 Bot 的 WebSocket 升级
POST /v1/events 批量写入记忆流
GET /v1/memory/crystals 列出晶体文件名
GET /v1/memory/crystals/{name} 读取单个晶体 Markdown

记忆实现

  • StreamStore：按事件日期追加 YYYY-MM-DD.jsonl，注释写明只增。
  • CrystalStore：读写 *.md，可列出与追加段落。
  • 默认目录来自环境变量 AGENT_OS_MEMORY_DIR / AGENT_OS_DATA_DIR；未设置时回落到 $HOME/projects/agent-os/...。

Cargo.toml 没有 SQLite 依赖。README 与 CLAUDE.md 把 SQLite 列为数据库选择，属于文档超前于实现。

Agent 引擎

AgentEngine trait 负责 spawn / send / subscribe / stop。三个适配器在源码中存在：

  • ClaudeCodeAdapter：调用本地 claude，使用 stream-json 输入输出。
  • KimiAdapter：查找本地 kimi 可执行文件。
  • CodexAdapter：查找本地 codex 可执行文件。

这证明仓库在对接本机 CLI，不能据此写成「已接入官方云 API 并完成评测」。README 的「Claude API」与适配器实现不是同一条路径。

客户端与 SDK

ContentView 使用 NavigationSplitView：侧栏机器人列表，详情为 ChatView；可打开创建设置表单与 SettingsView。网络层默认 http://127.0.0.1:3000，消息走 SSE。

LifeKit 提供 configure、track、按名 query 晶体、listen 洞察推送。其晶体查询 URL 为 /v1/crystals/{name}，与后端 /v1/memory/crystals/{name} 不一致。事件 POST 路径 /v1/events 与后端一致，请求体形状是否匹配未在本站验证运行时。

DashboardView 与若干 Sensor 类型存在于 app/ 并编进 Xcode 工程，但未被 ContentView 引用。仪表盘数字与「最近活动」在源码里是写死的示例，不是真实采集结果。

文档中的架构决策

下表来自 CLAUDE.md，表示作者意图，不保证每一项都已落地。

决策 文档选择 源码核对
